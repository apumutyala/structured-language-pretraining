# Preregistration: multi-seed replication of the normalized routing pilot

Written 2026-10-21, before any replicate in this package was trained or
evaluated. This file is frozen when it is committed; the commit must come
before the first replicate runs. Record any later deviation in the results
PR, and in `results/<tag>/DEVIATIONS.md` if there are any. Do not edit this file
after it is committed.

## 1. Background

The normalized 1,000-update local pilot
(`results/normalized_language_local_20261021.derived.json`) trained three
routing arms of an 8,703,788-parameter byte-level SSM from one paired random
initialization with one data order. It scored them on 12 DEV stories (3,060
byte targets) and 8 world questions:

| Arm | DEV story bpb | Typed requested-key acc. | Query-byte acc. |
| --- | ---: | ---: | ---: |
| none | 1.818783 | 8/8 | 1/8 |
| internal | 1.865863 | 7/8 | 1/8 |
| output_only | 1.819111 | 8/8 | 1/8 |

That is one seed and n=8 questions, which cannot separate an arm effect from
seed noise. This replication asks whether any difference survives seeds and a
much larger held-out evaluation.

## 2. Hypotheses

- **H1 (primary).** At matched compute, internal evidence routing improves
  (a) held-out typed requested-key accuracy, or (b) full-DEV story bits per
  UTF-8 byte, compared with no routing (`internal - none`). Matched compute
  means the same 1,000 Adam updates, the same 4,027,000 target tokens, the same
  initial parameters and data order within a replicate, and the same allocated
  parameter count. Active semantic parameters still differ by arm; the trainer
  reports this.
- **H2 (secondary).** The same contrasts for `output_only - none`.
- **Exploratory.** `internal - output_only`.

All tests are two-sided. A significant effect in the unfavorable direction is
reported as a reversal, not as a null.

## 3. Design

- **Trainer.** The trainer is the unchanged `tools/train_normalized_language_pilot.py`, which binds
  `tools/train_language_pilot.py`. It runs through `seeded_train.py`, which
  varies only `seed` and `data_seed` and leaves the rest of the original frozen
  validator in force. The base config is
  `configs/normalized_language_local_20261021.json` (stage `matched_stability`,
  FP32, length 128, 31 story rows + 1 world row per update, lr 3e-4, checkpoints
  0/50/200/500/1000).
- **Replicates.** A replicate is one trainer invocation that trains all three
  arms from the identical initialization (`torch.manual_seed(seed)`) on the
  identical batch stream (`data_seed`). The trainer asserts both.
  - Replicate 0 is the original seed pair (2026102131 / 2026102133) with the base
    config bytes reused unchanged. It is a **reproduction check only** and is
    **excluded from the primary analysis**, because those seeds produced the
    observation that motivated this study.
  - Replicates 1..10 are the primary sample: `seed = 2026102131 + 100k`,
    `data_seed = 2026102133 + 100k`, k = 1..10.
  - `dev_seed` and `sample_seed` are fixed, so in-run DEV batches are identical
    across replicates.
- **Hardware.** The single qualified local GPU (RTX 5070 Ti Laptop GPU) in FP32,
  with deterministic algorithms, as the trainer enforces.
- **Evaluated checkpoint.** Step 1000 (final) for every arm and replicate. No
  early stopping and no checkpoint selection.

## 4. Endpoints (computed by `eval_expanded.py`)

**Held-out world set.** This is every ledger in DEV folds 10..19 (404 of 4,096),
minus the 16 ledgers the trainer already used in its in-run DEV batches. That
leaves 388 ledgers × 4 queried keys = **1,552 questions**. The script checks
each replicate's actual training-world identities, which are read from that
replicate's report, and the run aborts if any of them overlaps the set.
Reserved folds 0..9 are not opened.

**Story set.** All 819 DEV documents (1,048,472 UTF-8 text bytes in the pinned
extraction).

| Role | Endpoint | Better | SESOI |
| --- | --- | --- | --- |
| **Primary P1** | Typed requested-key accuracy on the 1,552 held-out questions | higher | 0.02 (2 pp) |
| **Primary P2** | Story bits/UTF-8 byte, `tiled_full`: every DEV byte scored exactly once in BOS-prefixed ≤127-byte windows; EOS excluded from bpb, as in the trainer | lower | 0.01 bpb |
| Secondary | Raw query-byte (answer digit) accuracy; answer-byte NLL (bits); mean typed target probability; raw 41-way claim accuracy | — | 0.02 / 0.05 / 0.02 / 0.02 |
| Secondary | Story bpb using the trainer's own window protocol on all 819 docs; story bpb on the original 12-doc in-run DEV set (replayed) | lower | 0.01 |
| Diagnostic | Typed non-abstention coverage; forbidden probability mass | — | — |

SESOI is the smallest effect size of interest.

Forbidden mass is zero by construction of the exact evidence decoder. It is
only a correctness check, and any nonzero value is a bug, not an outcome.

The typed task is structural. In a world row all four keys are observed
singletons, so the decoder admits exactly four claims plus abstain. Typed
accuracy therefore measures whether the model identifies the queried key.
Chance is about 1/5 for typed accuracy and 1/8 for the query byte.

## 5. Analysis and decision rule (`analyze.py`)

**Unit of analysis.** The replicate. For each endpoint the per-replicate
paired difference is d_k = metric(arm) − metric(none).

**Statistics reported.**
- Per-arm mean and SD.
- Mean and SD of d.
- Percentile bootstrap 95% CI over replicates: 10,000 resamples, seed 20261021.
- Two-sided paired t-test with its 95% t-CI.
- Exact two-sided sign test, ties dropped.
- Exact sign-flip permutation p.

**Multiplicity.** Holm correction over the two primary `internal - none`
t-tests (P1 and P2). Secondary endpoints and H2 are reported unadjusted and
labeled as such.

**Verdict for each primary endpoint:**
- **SUPPORTED** when all of the following hold:
  - Holm p < 0.05;
  - the bootstrap CI excludes 0;
  - the effect is in the favorable direction;
  - |mean d| ≥ SESOI.

  When the effect is significant and favorable but below SESOI, it is reported
  as a *practically negligible* improvement and does not support H1.
- **REVERSED** when Holm p < 0.05, the bootstrap CI excludes 0, and the effect
  is unfavorable.
- **NULL (equivalence)** when it is not significant and the 95% t-CI lies
  entirely within ±SESOI.
- **NULL (inconclusive)** in every other case.

**Overall result.**
- **H1 is supported** if at least one primary endpoint is SUPPORTED and neither
  is REVERSED.
- **MIXED** if one is SUPPORTED and the other is REVERSED.
- Otherwise H1 is **not supported**.

**What counts as a null.** H1 has a null result when neither primary endpoint
is SUPPORTED. A NULL (equivalence) result is evidence that any effect is
smaller than SESOI at this scale. A NULL (inconclusive) result means the study
lacked the precision to decide.

**Typed ceiling rule.** If the none-arm mean typed accuracy is ≥ 0.995, an
improvement of at least SESOI is impossible, and P1 is labeled ceiling-limited.

**Power.** With n = 10 pairs, a two-sided paired t-test has 80% power only for
standardized effects d_z ≈ 1.0 at α = 0.05, or d_z ≈ 1.14 at the Holm-first
α = 0.025. Smaller effects will often appear as NULL (inconclusive).

## 6. Failures, exclusions, stopping

- **Failed replicates.** If a replicate fails (non-finite loss or gradient,
  wall or memory cap, assertion), it is reported with its arm-level status. It
  is never silently replaced or overwritten. An instability confined to one arm
  is itself a reportable finding.
- **Minimum sample.** The primary analysis uses replicates that have all three
  arms complete. With fewer than 8 such replicates the result is INCONCLUSIVE.
- **Extra replicates.** Replicates beyond 10, if run, are appended in index
  order (11, 12, …), and all of them are reported. The primary result uses
  1..10 unless failures force using the next indices in order, and that must be
  stated.
- **No peeking.** No interim analysis and no checkpoint or hyperparameter
  selection.
- **Replicate 0 reproduction.** Replicate 0 is compared with the original
  receipt: the init digest, batch digest and final checkpoint digest must be
  exactly equal, and the bpb difference is reported. A mismatch is reported,
  for example from a different torch/driver build. It does not invalidate
  replicates 1..10, but the torch version and device must be stated.

## 7. Limitations fixed in advance

- DEV is a development split, not a sealed test.
- There is one model size (8.7M) and one short horizon (1,000 updates).
- The world facts also appear in the text for all arms.
- The evidence routing only changes how the exact evidence reaches the
  network.
- This is not the matched external-workspace experiment in
  `docs/experiments.md`.
- No result here establishes a semantic-integration, safety or architecture
  advantage beyond these endpoints.
