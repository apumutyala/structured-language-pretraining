# Primary matched-interface question

The proposed primary contrast holds the SSM architecture fixed and compares
internal exact-state integration against an equally informed external-workspace
interface. A Transformer reference is optional context, not the primary
architectural claim. The present adapter only exposes the interface; it is not
a trained strong external baseline or a completed experimental registration.

All learners start from random initialization. Both arms receive the same
facts, rules, current permissions, intermediate results, revisions and failure
feedback. They share operation grammar and checker, and failed/invalid attempts
consume operation budget. Match model/data/token/optimization budgets and
report trainable/active parameter differences. Charge serialization, encoding,
context tokens, checker work, planning, failed proposals, fallback, tuning and
evaluation. Logical information equality alone is insufficient: add an
encoding-matched control and measure effective observation bandwidth/context
cost before assigning a causal effect to semantic integration.

Specify learned-cache carry/reset rules for every arm. Give the external
planner persistent state and the same intermediate reads before its next
decision. Internal per-layer reads and serialized model-call loops have
different schedules: cost those differences and allow adequate planner steps.
Pair shape-compatible random initial values, data order and tuning allowances;
report active gradient paths as well as allocated parameter counts.

The primary proposed endpoint is useful, correct, supported answers on held-out
paraphrase and compositional tasks at frozen language-quality and total-cost
tolerances. Report answer accuracy, useful coverage, refusals, fallback use,
invalid-attempt frequency, question/program interpretation errors, unsupported
release attempts and stale-answer rates separately. A checker that refuses
everything does not pass usefulness. Fix practical margins, tests, sample sizes
and paired confidence-interval analysis before confirmation; no current pilot
establishes these floors or broad safety.

Required controls include a strong trained external planner using the same
information and feedback, an exact-kernel-only baseline and an oracle planner.
The latter two receive a parsed goal only in their explicitly labeled setting;
solving that goal measures execution/planning rather than natural-language
understanding. Do not pass oracle answers or future labels into learner inputs.
Include evidence shuffle/drop, untrusted authority text, counterfactual evidence
replacement and revocation, policy changes, long histories, no-answer cases,
conjunctions and stale-certificate/epoch attempts. Evaluate selective coverage
and calibration without trading support/permission floors for raw accuracy.

Split completion groups and exact normalized duplicates before train/dev;
reserve new task families, paraphrases and compositions for sealed confirmation.
The existing SimpleStories extraction uses only one TRAIN shard and exact
normalization/group exclusion, with no template or near-duplicate guarantee.
Do not present that development corpus as a clean broad language benchmark.

The illustrative discovery grid has two interfaces, two data conditions,
three paired seeds and two model sizes (125M/350M): 24 runs. A six-run roughly
1B extension is conditional on useful learning, stability, safety/control and
measured all-in affordability. Twelve optional Transformer reference runs are
secondary and first to be cut if they displace the primary comparison. These
are planning scenarios, not completed recipes or commitments. Every failed
seed and diagnostic/tuning cost must remain visible. The small historical
none/internal/output-only pilot is not this future matched-interface experiment.
